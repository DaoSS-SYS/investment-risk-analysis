## Назначение системы

Система автоматизирует сбор биржевых данных и количественную оценку рисков
инвестиционной деятельности на фондовом рынке. Исходными данными служат
открытые исторические данные Московской Биржи и макроэкономические показатели
Банка России.

Реализуемые методы количественной оценки риска:

- стоимостная мера риска Value at Risk тремя методами — параметрическим
  (дельта-нормальным), историческим и методом Монте-Карло;
- ожидаемые потери Expected Shortfall (условная стоимостная мера риска CVaR);
- оценка волатильности: скользящая оценка и экспоненциально взвешенная
  оценка EWMA;
- коэффициенты эффективности: Шарпа, Сортино, Трейнора, информационный
  коэффициент, максимальная просадка;
- модель оценки капитальных активов CAPM: коэффициент бета, альфа Йенсена;
- бэктестирование моделей VaR: тест Купца на частоту нарушений, тест
  Кристоферсена на независимость нарушений, подход Базельского комитета;
- стресс-тестирование по историческим и гипотетическим сценариям;
- оптимизация структуры портфеля по модели Марковица.

## Развёртывание

Требуется: .NET SDK 10, PostgreSQL 17, Node.js 22 и выше (для клиентской части).

1. Создать базу данных:

   ```
   createdb -U postgres riskanalysis
   ```

2. Задать строку подключения. В среде разработки она хранится в User Secrets и
   не попадает в репозиторий:

   ```
   dotnet user-secrets --project backend/src/RiskAnalysis.WebApi set "ConnectionStrings:Default" "Host=localhost;Port=5432;Database=riskanalysis;Username=postgres;Password=<пароль>"
   ```

3. Применить миграции:

   ```
   dotnet ef database update --project backend/src/RiskAnalysis.Infrastructure --startup-project backend/src/RiskAnalysis.WebApi
   ```

4. Запустить серверную часть:

   ```
   dotnet run --project backend/src/RiskAnalysis.WebApi
   ```

5. Запустить клиентскую часть:

   ```
   cd frontend
   npm install
   npm run dev
   ```

   Приложение открывается по адресу `http://localhost:5173`. Запросы к
   программному интерфейсу перенаправляются на сервер прокси сборщика.
   Для показа с другого компьютера локальной сети используется адрес узла,
   например `http://192.168.33.134:5173`.

Документация программного интерфейса доступна по адресу `/swagger`, проверка
работоспособности — по адресу `/health`, сведения о состоянии хранилища
данных — по адресу `/api/system/info`.
