## Назначение системы

Система автоматизирует сбор биржевых данных и количественную оценку рисков
инвестиционной деятельности на фондовом рынке. Исходными данными служат
открытые исторические данные Московской Биржи и макроэкономические показатели
Банка России.

Реализуемые методы количественной оценки риска:

- стоимостная мера риска Value at Risk тремя методами — параметрическим
  (дельта-нормальным), историческим и методом Монте-Карло;
- ожидаемые потери Expected Shortfall (условная стоимостная мера риска CVaR);
- оценка волатильности: скользящая оценка, экспоненциально взвешенная
  оценка EWMA и модель GARCH(1,1) с оцениванием параметров методом
  максимального правдоподобия;
- фильтрованное историческое моделирование, соединяющее условную оценку
  волатильности с эмпирическим распределением доходностей;
- коэффициенты эффективности: Шарпа, Сортино, Трейнора, информационный
  коэффициент, максимальная просадка;
- модель оценки капитальных активов CAPM: коэффициент бета, альфа Йенсена;
- бэктестирование моделей VaR: тест Купца на частоту нарушений, тест
  Кристоферсена на независимость нарушений, подход Базельского комитета;
- стресс-тестирование по историческим и гипотетическим сценариям;
- оптимизация структуры портфеля по модели Марковица: эффективная граница,
  портфель наименьшей дисперсии, касательный портфель, ограничение
  предельной доли инструмента.

## Разграничение прав доступа

Доступ к программному интерфейсу предоставляется после проверки
подлинности. Предусмотрены три роли:

| Роль | Полномочия |
| --- | --- |
| Наблюдатель | Ознакомление со всеми портфелями, результатами расчётов и отчётами без права изменения данных |
| Аналитик | Полномочия наблюдателя, а также ведение собственных портфелей, выполнение расчётов по любым портфелям, формирование отчётов |
| Администратор | Полномочия аналитика, а также ведение справочника инструментов, загрузка данных из внешних источников, управление учётными записями, просмотр журнала действий |

Изменять состав портфеля вправе создавший его пользователь и
администратор. Действия, изменяющие состояние системы, фиксируются
в журнале: он позволяет установить, вызвано ли изменение оценки риска
изменением рыночных условий либо изменением состава портфеля.

Основания принятых решений и известные ограничения приведены в
[ADR-0015](docs/adr/0015-autentifikaciya-i-razgranichenie-dostupa.md).

## Развёртывание

Предусмотрены два порядка: развёртывание в контейнерах — основной,
и запуск из исходного кода — для разработки.

### Развёртывание в контейнерах

Требуется: Docker и Docker Compose. Устанавливать .NET SDK, Node.js
и PostgreSQL на машине развёртывания не нужно.

1. Заполнить файл параметров:

   ```
   cp .env.example .env
   ```

   Задать `POSTGRES_PASSWORD`, `JWT_SIGNING_KEY` (не короче 32 знаков)
   и `ADMIN_PASSWORD`. Значений по умолчанию для них не предусмотрено:
   без них составление прекращается с указанием незаданного параметра.

2. Запустить:

   ```
   docker compose up --build --detach
   ```

   При первом запуске применяются миграции, создаются роли и учётная
   запись `admin` с паролем из `ADMIN_PASSWORD`.

3. Открыть `http://localhost:8080`.

Состояние служб — `docker compose ps`, журнал серверной части —
`docker compose logs --follow backend`, остановка — `docker compose down`
(данные сохраняются в именованном томе; для их удаления —
`docker compose down --volumes`).

Основания принятых решений и известные ограничения приведены в
[ADR-0016](docs/adr/0016-razvyortyvanie-v-konteynerah.md).

### Запуск из исходного кода

Требуется: .NET SDK 10, PostgreSQL 17, Node.js 22 и выше (для клиентской части).

1. Создать базу данных:

   ```
   createdb -U postgres riskanalysis
   ```

2. Задать строку подключения. В среде разработки она хранится в User Secrets и
   не попадает в репозиторий:

   ```
   dotnet user-secrets --project backend/src/RiskAnalysis.WebApi set "ConnectionStrings:Default" "Host=localhost;Port=5432;Database=riskanalysis;Username=postgres;Password=<пароль>"
   ```

3. Задать ключ подписи маркеров доступа и пароль учётной записи
   администратора, создаваемой при первом запуске. Значения по умолчанию
   не предусмотрены: без них приложение не запускается.

   ```
   dotnet user-secrets --project backend/src/RiskAnalysis.WebApi set "Jwt:SigningKey" "<строка не короче 32 знаков>"
   dotnet user-secrets --project backend/src/RiskAnalysis.WebApi set "Seed:AdministratorPassword" "<пароль>"
   ```

4. Применить миграции:

   ```
   dotnet ef database update --project backend/src/RiskAnalysis.Infrastructure --startup-project backend/src/RiskAnalysis.WebApi
   ```

5. Запустить серверную часть:

   ```
   dotnet run --project backend/src/RiskAnalysis.WebApi
   ```

6. Запустить клиентскую часть:

   ```
   cd frontend
   npm install
   npm run dev
   ```

   Приложение открывается по адресу `http://localhost:5173`. При первом
   запуске создаются роли и учётная запись `admin` с паролем, заданным
   параметром `Seed:AdministratorPassword`; остальные учётные записи
   создаются в разделе «Администрирование». Запросы к
   программному интерфейсу перенаправляются на сервер прокси сборщика.
   Для показа с другого компьютера локальной сети используется адрес узла,
   например `http://192.168.33.134:5173`.

Документация программного интерфейса доступна по адресу `/swagger`, проверка
работоспособности — по адресу `/health`, сведения о состоянии хранилища
данных — по адресу `/api/system/info`.
