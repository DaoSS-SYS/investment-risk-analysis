# ADR-0001. Ведение журнала архитектурных решений

- **Статус:** принято
- **Дата:** 2026-09-23

## Контекст

Разработка информационной системы ведётся в рамках выпускной квалификационной
работы. Во второй главе работы требуется обосновать принятые архитектурные
решения, а методические рекомендации кафедры прямо указывают на применение
практик формализации архитектурных решений в программировании (метод ADR —
Architecture Decision Records).

Решения, принимаемые в ходе разработки, со временем забываются, а их
восстановление по исходному коду требует значительных трудозатрат.

## Решение

Каждое значимое архитектурное решение фиксируется отдельным документом в
каталоге `docs/adr` в формате «контекст — решение — последствия». Документы
нумеруются последовательно и не удаляются: принятое ранее решение может быть
отменено новым ADR со ссылкой на отменяемый документ.

## Последствия

Положительные:

- материал для параграфов 2.1 и 2.3 выпускной квалификационной работы
  накапливается непрерывно, а не восстанавливается в конце разработки;
- история решений с датами подтверждает самостоятельный характер разработки;
- обоснование выбора технологий фиксируется в момент выбора, когда аргументы
  ещё актуальны.

Отрицательные:

- требуется дисциплина ведения записей в ходе разработки.
