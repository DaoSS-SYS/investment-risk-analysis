# ADR-0003. PostgreSQL в качестве основного хранилища данных

- **Статус:** принято
- **Дата:** 2026-09-23

## Контекст

Система хранит два принципиально разных вида данных:

1. Строго структурированные временные ряды котировок. Ожидаемый объём —
   порядка 30 инструментов за 10 лет дневной истории, то есть около 75 тысяч
   записей; нагрузка на чтение существенно превышает нагрузку на запись.
2. Параметры и результаты расчётов, состав которых различается в зависимости от
   применяемого метода оценки риска и расширяется по мере добавления новых
   моделей.

## Решение

В качестве системы управления базами данных принимается PostgreSQL 17.

Основания выбора:

- поддержка типа `jsonb` с индексацией позволяет хранить разнородные параметры
  и результаты расчётов без создания отдельной таблицы под каждый метод;
- оконные функции (`LAG`, `OVER`) дают возможность вычислять доходности
  непосредственно средствами СУБД при проверке результатов расчётного ядра;
- свободная лицензия и отсутствие ограничений на применение;
- зрелый провайдер Npgsql для Entity Framework Core с поддержкой типов
  `DateOnly` и `jsonb`.

Рассмотренное и отклонённое расширение TimescaleDB: при фактическом объёме
данных порядка 10^5 записей выигрыш от гипертаблиц отсутствует, а усложнение
развёртывания повышает риск отказа при демонстрации системы.

## Последствия

Положительные:

- схема данных не требует изменения при добавлении новых методов анализа;
- результаты расчётов проверяются независимым запросом на языке SQL.

Отрицательные:

- содержимое полей `jsonb` не контролируется схемой базы данных; корректность
  структуры обеспечивается на уровне приложения.
