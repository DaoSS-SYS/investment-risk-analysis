# ADR-0016. Развёртывание в контейнерах

- **Статус:** принято
- **Дата:** 2026-09-26

## Контекст

Система состоит из трёх частей: хранилища данных, серверного приложения
и клиентского приложения. До настоящего этапа их запуск описывался
последовательностью действий в руководстве: создать базу данных, задать
строку подключения, применить миграции, запустить сервер, установить
зависимости клиентской части, запустить сборщик.

Такой порядок имеет два недостатка. Первый: воспроизведение системы
на другой машине требует установки .NET SDK, Node.js и PostgreSQL
согласованных версий, и расхождение версий приводит к отказам, причина
которых неочевидна. Второй: раздел «внедрение» выпускной
квалификационной работы требует описания порядка развёртывания, а
перечень действий, выполняемых вручную, описанием развёртывания
считаться не может.

## Решение: составление из трёх служб

Применяется Docker Compose. Описаны три службы: `database`, `backend`,
`frontend`.

Развёртывание системы сводится к двум действиям: заполнить файл
параметров и выполнить одну команду. Устанавливать .NET SDK, Node.js
и PostgreSQL на машине развёртывания не требуется — требуется только
средство запуска контейнеров.

Порядок запуска задан явно через условия готовности, а не через простое
указание очерёдности. Серверная часть запускается **после успешной
проверки готовности** СУБД принимать соединения: указание одной лишь
очерёдности означало бы запуск после создания контейнера СУБД, но
до её готовности, и применение миграций завершилось бы отказом.
Клиентская часть, в свою очередь, ожидает готовности серверной.

## Решение: двухэтапная сборка образов

Образы обеих частей собираются в два этапа. На первом применяется образ
со средствами разработки, на втором в образ среды выполнения копируется
только результат сборки.

Основание: средства разработки в готовом образе не нужны. Их исключение
сокращает объём образа и уменьшает число содержащихся в нём программ,
а значит и число возможных уязвимостей. Для клиентской части эффект
особенно нагляден: результат её сборки — набор файлов разметки, стилей
и сценариев, для отдачи которых среда выполнения Node.js не требуется
вовсе.

Файлы с перечнями зависимостей копируются отдельно и **прежде**
исходного кода. Основание: сборщик образов кеширует результат каждой
команды и повторяет её только при изменении входных данных. Перечень
зависимостей изменяется редко, исходный код — часто. При таком порядке
изменение кода не приводит к повторной загрузке пакетов из сети.

Для клиентской части применяется команда `npm ci`, а не `npm install`:
она устанавливает версии строго по `package-lock.json` и не изменяет
его, благодаря чему повторная сборка образа даёт тот же состав
зависимостей.

## Решение: установка шрифтов в образ

Ограничение, зафиксированное в [ADR-0014](0014-formirovanie-otchyotov.md),
устраняется на настоящем этапе.

Образ среды выполнения ASP.NET шрифтов не содержит, а поставляемый
с библиотекой QuestPDF шрифт Lato не имеет начертаний букв
кириллического алфавита. Без установки шрифтов отчёты формировались бы
с неотображаемыми знаками вместо русского текста.

В образ устанавливаются семейства DejaVu Sans и Liberation Sans — оба
входят в перечень, просматриваемый при выборе шрифта, и оба содержат
кириллические начертания.

## Решение: отдача клиентского приложения и перенаправление запросов

Собранное клиентское приложение отдаётся сервером nginx. Он же
перенаправляет обращения по адресам `/api/` и `/health` на серверную
часть.

Существенное следствие: браузер обращается к программному интерфейсу
по тому же адресу, с которого загружено приложение, и механизм
разделения ресурсов между источниками (CORS) не задействуется вовсе.
Тот же порядок принят и в среде разработки, где перенаправление
выполняет сервер сборщика Vite. Настройка разрешённых источников
остаётся в приложении, но при таком размещении не применяется.

Отдельное правило требуется для маршрутизации на стороне клиента:
адресу `/portfolios/1` не соответствует файл на диске. При отсутствии
запрошенного файла отдаётся `index.html`, и маршрут разбирает само
приложение. Без этого правила обновление страницы по такому адресу
давало бы ответ 404.

## Решение: применение миграций при запуске

Введён параметр `Database:MigrateOnStartup`. В среде разработки он
выключен: миграции применяются вручную командой `dotnet ef database
update`. При размещении в контейнере он включается, поскольку выполнить
команду вручную внутри контейнера негде.

При запуске приложение получает перечень неприменённых миграций,
записывает его в журнал и применяет их.

Ограничение порядка названо явно: при одновременном запуске нескольких
экземпляров приложения миграции попытались бы примениться одновременно.
Для рассматриваемой системы это несущественно — экземпляр один; при
переходе к нескольким экземплярам применение миграций следует выделить
в отдельный шаг развёртывания.

## Решение: параметры, составляющие тайну, вне репозитория

Репозиторий является общедоступным. Пароль к базе данных, ключ подписи
маркеров доступа и пароль учётной записи администратора не содержатся
ни в файле составления, ни в образах. Они берутся из файла `.env`,
который указан в `.gitignore`; образец его состава приведён
в `.env.example`.

Значений по умолчанию для этих трёх параметров **не предусмотрено
намеренно**: при их отсутствии составление прекращается с сообщением
о том, какой именно параметр не задан. Основание то же, что и
в [ADR-0015](0015-autentifikaciya-i-razgranichenie-dostupa.md): значение
по умолчанию, пригодное для запуска, с высокой вероятностью осталось бы
неизменным.

Данные СУБД размещаются в именованном томе, а не внутри контейнера:
контейнер пересоздаётся при обновлении образа, и без тома история
котировок терялась бы при каждом обновлении приложения.

Серверное приложение выполняется от имени непривилегированного
пользователя, содержащегося в образе ASP.NET.

## Результаты апробации

Средство запуска контейнеров на машине разработки не установлено,
поэтому проверка выполнена в той части, которая от него не зависит.

Проверено:

- файл составления разбирается без ошибок; описаны три службы, один
  именованный том, одна сеть; условия готовности связывают службы
  в требуемом порядке;
- все файлы проектов, перечисленные в образе серверной части,
  существуют по указанным путям;
- сборка серверного приложения в конфигурации Release выполняется без
  ошибок;
- пути установки шрифтов, создаваемые пакетами `fonts-dejavu-core`
  и `fonts-liberation`, совпадают с путями, просматриваемыми при выборе
  шрифта;
- параметр `Database:MigrateOnStartup` читается из переменной окружения
  в том виде, в каком её задаёт файл составления
  (`Database__MigrateOnStartup`).

Проверено применение миграций к **пустой** базе данных — то есть
последовательность, выполняемая при первом запуске системы. На вновь
созданной базе данных приложение применило три миграции
(`InitialSchema`, `CorporateActions`, `IdentityAndAudit`), создав
17 таблиц, создало три роли и учётную запись администратора; вход
в систему выполнен успешно.

**Не проверено:** сборка образов и запуск составления. Проверка требует
установленного средства запуска контейнеров и должна быть выполнена
до защиты.

## Последствия

Положительные:

- развёртывание системы сводится к заполнению файла параметров и одной
  команде; установка .NET SDK, Node.js и PostgreSQL на машине
  развёртывания не требуется;
- устранено ограничение ADR-0014: отчёты формируются с кириллическими
  начертаниями и в контейнере;
- раздел «внедрение» выпускной квалификационной работы получает
  описание порядка развёртывания, пригодное для воспроизведения;
- согласованность версий среды выполнения обеспечивается составом
  образов, а не действиями устанавливающего.

Отрицательные и известные ограничения:

- обмен выполняется по незащищённому протоколу; при размещении в сети
  общего пользования требуется TLS, без которого маркер доступа может
  быть перехвачен. Получение сертификата в состав настоящей работы
  не входит;
- применение миграций при запуске непригодно для нескольких
  одновременно запускаемых экземпляров приложения;
- порядок обновления системы без остановки обслуживания не
  предусмотрен: при обновлении образов службы перезапускаются;
- резервное копирование базы данных не автоматизировано; том
  сохраняется при пересоздании контейнеров, но не защищён от удаления
  тома;
- сборка образов требует доступа к сети для загрузки пакетов .NET и
  npm; в изолированной среде потребовался бы собственный узел хранения
  пакетов.
