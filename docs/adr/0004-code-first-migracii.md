# ADR-0004. Подход Code First и миграции EF Core

- **Статус:** принято
- **Дата:** 2026-09-23

## Контекст

Схема базы данных в ходе разработки изменяется многократно: подсистемы
аутентификации, стресс-тестирования и бэктестирования добавляются поэтапно.
Требуется воспроизводимое развёртывание базы данных на произвольной машине —
в частности, при демонстрации системы на предварительной защите.

## Решение

Применяется подход Code First: схема базы данных порождается из классов
предметной области, изменения схемы оформляются миграциями Entity Framework
Core.

Конфигурация сущностей вынесена в отдельные классы, реализующие интерфейс
`IEntityTypeConfiguration<T>`, вместо настройки в методе `OnModelCreating`.

Имена таблиц и столбцов формируются в стиле `snake_case` пакетом
`EFCore.NamingConventions` — в соответствии с соглашением об именовании,
принятым в PostgreSQL.

Для средств проектирования реализована фабрика `RiskAnalysisDbContextFactory`
(интерфейс `IDesignTimeDbContextFactory`), благодаря чему создание миграций не
требует запуска веб-приложения и не зависит от наличия строки подключения в
конфигурации приложения.

## Последствия

Положительные:

- история изменений схемы данных хранится в репозитории и датирована;
- развёртывание базы данных выполняется одной командой `dotnet ef database update`;
- сценарий SQL для приложения к работе выгружается командой
  `dotnet ef migrations script --idempotent`.

Отрицательные:

- порождаемый код миграций требует проверки перед применением;
- откат применённой миграции на заполненной базе данных требует отдельного
  сценария переноса данных.
