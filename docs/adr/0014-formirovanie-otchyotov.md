# ADR-0014. Формирование отчётов

- **Статус:** принято
- **Дата:** 2026-09-25

## Контекст

Результаты расчётов доступны через программный интерфейс и представлены
в клиентском приложении. Для практического применения этого недостаточно:
результаты анализа риска требуется представлять руководству, приобщать
к документации и передавать для дальнейшей обработки.

Требуются две различные формы представления с несовпадающими требованиями.

## Решение: два формата с разным назначением

**Переносимый документ (PDF)** предназначен для чтения и приобщения
к документации. Существенны постоянство разметки, пригодность для печати
и невозможность случайного изменения. Применяется библиотека QuestPDF.

**Электронная таблица (XLSX)** предназначена для дальнейшей обработки
данных пользователем. Существенно, чтобы числовые величины записывались
числами, а не строками, и снабжались форматами отображения: это позволяет
строить собственные диаграммы и выполнять дополнительные расчёты без
повторного ввода данных. Применяется библиотека ClosedXML.

В строке итогов листа разложения риска записаны не вычисленные значения,
а формулы суммирования. Пользователь может убедиться в выполнении тождества
Эйлера средствами самого табличного процессора.

## Решение: разделение сбора данных и разметки

Построители отчётов не обращаются ни к базе данных, ни к расчётным службам.
Они получают готовые объекты — портфель с переоценкой, результат оценки
риска, результат стресс-тестирования — и занимаются исключительно разметкой.

Сбор сведений выполняет отдельная служба. Такое разделение позволяет
проверять построители на произвольных данных и добавлять новые форматы,
не затрагивая расчётную часть.

Невозможность выполнить стресс-тестирование не препятствует формированию
отчёта: соответствующий раздел в него не включается, а причина фиксируется
в журнале. Отчёт по портфелю, история котировок по которому неполна,
должен формироваться, пусть и в сокращённом виде.

## Решение: явная регистрация шрифта

При первой проверке построение документа прерывалось сообщением о
недоступности семейства шрифта.

Причины две. Первая: поставляемый с библиотекой QuestPDF шрифт Lato не
содержит начертаний букв кириллического алфавита. Вторая: начиная с версии
2026.9 библиотека не обращается к установленным в системе шрифтам по
умолчанию.

Первая попытка устранения — включение обращения к системным шрифтам и
указание перечня запасных семейств — оказалась недостаточной: библиотека
прерывает построение при указании **любого** недоступного семейства, даже
если доступные в перечне присутствуют. Перечень «Segoe UI, Arial,
DejaVu Sans, Liberation Sans» приводил к отказу на машине под управлением
Windows, поскольку два последних семейства в ней отсутствуют.

Принятое решение: при первом обращении просматриваются известные
расположения файлов шрифтов, и регистрируется первое найденное семейство,
содержащее кириллические начертания. Проверяются расположения, принятые
в операционных системах семейства Windows (Segoe UI, Arial) и в
дистрибутивах Linux (DejaVu Sans, Liberation Sans). Регистрируются файлы
обычного и полужирного начертаний: полужирное требуется для заголовков
и строк итогов.

Такой порядок делает построение отчёта воспроизводимым независимо от
операционной системы и не требует включения файлов шрифтов в состав
репозитория.

## Состав отчёта

| Раздел | Содержание |
| --- | --- |
| Общие сведения | Период выборки, стоимость портфеля, финансовый результат, параметры расчёта, волатильность, эффект диверсификации |
| Состав портфеля | Позиции с переоценкой по последним котировкам, доли |
| Оценка риска | Стоимостная мера риска и ожидаемые потери всеми реализованными методами |
| Разложение риска | Компонентная, предельная и обособленная меры риска по позициям, выигрыш от диверсификации |
| Стресс-тестирование | Исторические и гипотетические сценарии, отношение потерь к мере риска |
| Выводы | Формулировки, полученные расчётными службами |

Позиции, вклад которых в риск превышает их долю в портфеле, выделены
цветом в обоих форматах.

## Результаты апробации

Отчёт по модельному портфелю из пяти акций:

- переносимый документ — 2 страницы, 54 278 байт, все шесть разделов,
  кириллические начертания и знак рубля отображаются верно;
- электронная таблица — 5 листов, 15 704 байта: «Общие сведения»,
  «Состав портфеля», «Оценка риска», «Разложение риска»,
  «Стресс-тестирование».

Имя файла формируется из наименования портфеля и даты, недопустимые
в именах файлов символы заменяются. Имя передаётся в заголовке
Content-Disposition в кодировке UTF-8, что обеспечивает корректное
сохранение файлов с наименованиями на русском языке.

## Последствия

Положительные:

- закрыто требование к информационной системе о формировании отчётных
  документов;
- сформированные отчёты пригодны для приобщения к выпускной
  квалификационной работе в качестве приложений;
- формулы в строке итогов позволяют проверить тождество Эйлера
  средствами табличного процессора, независимо от системы.

Отрицательные и известные ограничения:

- при размещении приложения в контейнере требуемые шрифты должны быть
  установлены в образе; при отсутствии всех проверяемых семейств документ
  формируется шрифтом Lato, в котором кириллические начертания отсутствуют;
- диаграммы в отчёты не включаются: их построение потребовало бы
  отрисовки на стороне сервера, тогда как в клиентском приложении они
  уже представлены;
- отчёт формируется в ходе обработки запроса; при значительном числе
  инструментов следует применять постановку в очередь по образцу
  расчётов риска (см. [ADR-0010](0010-risk-portfelya-i-asinhronnye-raschety.md)).
