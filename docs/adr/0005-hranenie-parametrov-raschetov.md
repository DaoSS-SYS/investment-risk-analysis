# ADR-0005. Хранение параметров и результатов расчётов в поле jsonb

- **Статус:** принято
- **Дата:** 2026-09-23

## Контекст

Система выполняет расчёты четырёх видов: оценка риска, бэктестирование модели
VaR, оптимизация портфеля и стресс-тестирование. Наборы входных параметров и
результатов у них не совпадают:

- параметрический метод VaR требует уровня доверия, горизонта и глубины
  выборки;
- метод Монте-Карло дополнительно требует числа сценариев и начального
  значения генератора псевдослучайных чисел;
- бэктестирование требует периода проверки и проверяемого метода;
- оптимизация требует ограничений на доли инструментов в портфеле.

Проектирование отдельной таблицы под каждый вид расчёта привело бы к семи и
более таблицам с пересекающимся составом полей и к необходимости новой миграции
при добавлении каждого метода.

## Решение

Все расчёты хранятся в единой таблице `risk_calculations`. Вид расчёта
определяется полем `calculation_type`, параметры запуска и результат хранятся в
полях `parameters_json` и `result_json` типа `jsonb`.

Структура содержимого этих полей задаётся типами языка C# в слое приложения и
проверяется при десериализации.

Сохранение параметров вместе с результатом обеспечивает:

- воспроизводимость расчёта — по сохранённым параметрам расчёт повторяется и
  даёт тот же результат;
- кэширование — повторный запрос с теми же параметрами не требует повторного
  вычисления;
- построение динамики риск-показателей во времени по истории расчётов.

## Последствия

Положительные:

- добавление нового метода анализа не требует изменения схемы данных;
- журнал расчётов служит источником данных для оценки производительности
  системы (поле `duration_ms`).

Отрицательные:

- отсутствует контроль структуры на уровне СУБД;
- изменение формата результата требует обработки ранее сохранённых записей.
